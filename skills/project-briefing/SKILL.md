# 项目简报

为工作目录里的项目生成一份让人 10 分钟看懂的简报。

## 档位

- **快速档**：用户说"快速过一遍/简单介绍"→ 全文 ≤40 行，只回答"是什么、用什么、怎么跑、最近干嘛"。
- **标准档**（默认）：完整骨架，全文 ≤150 行。

## 流程

1. **采集**：用 glob 列顶层结构、定位清单文件（README、pom.xml/package.json/go.mod 等）；用 readFile 读清单、入口类与核心配置；用 Bash 执行
   `git log --oneline -15 && git branch --show-current && git status --short`
   非 git 仓库会报错，属正常信号——跳过"近期动态"板块并在简报中写明原因。
2. **归类**：后端/通用项目按下方骨架写；前端/库/monorepo 把"架构与模块地图"换成"路由与页面地图"，并补"构建与环境"（scripts 原文、环境变量名、锁文件判断包管理器）；文件总数 <10 的项目不套骨架，直接描述现状并列出已有文件。
3. **成文**：按骨架写。缺料的板块明确写"未发现"，不删板块、不硬凑；每条结论要有文件路径或命令输出作依据。

## 输出骨架

- 头部：`# {项目名} 项目简报` + 日期、分支@commit 短哈希、目录路径
- 一句话定位：做什么、给谁用、什么阶段；推断的句尾标"(推断)"
- 技术栈：层面/选型/版本 表格——版本只取清单文件字面值，取不到写"未知"或"由 parent 管理"
- 架构与模块地图：一段架构说明 + 目录职责表
- 入口与运行：启动入口完整路径、本地运行命令（读不到写"未确认"）、部署方式（无则"未发现"）
- 近期动态：git log 归纳 3-5 条开发方向，附代表性提交主题
- 风险与技术债：3-5 条，每条附证据路径（无测试、密钥明文这类问题发现必写）
- 快速上手清单：新人第一天该做的 3-5 件事

## 红线

- 每个路径必须真实存在、每个版本号可溯源到清单字段——不凭记忆、不臆测；交付前抽 3 个路径用 glob 验证。
- 篇幅超限先砍"近期动态"细节和目录表行数，不砍"风险"和"快速上手"。
- 交付前通读一遍，"这句的依据是什么"答不上来的句子删掉；证据不足就降级表述，宁写"未确认"不写猜测。
